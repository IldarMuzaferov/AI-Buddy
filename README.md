# «Путь стажёра» (AI-Buddy)

Прототип ИИ-помощника для онбординга стажёра: отвечает по внутренним документам с указанием источников, помогает с чек-листом и задачами, предлагает контакты и ведёт журнал достижений. Наставник может видеть прогресс стажёра, но не его чаты и сообщения.

> В репозитории только вымышленные пользователи, документы и сервисы. Это демонстрационные данные, а не регламенты Авито. Прототип не предназначен для обработки реальных персональных данных или эксплуатации в production.

## Запуск всего прототипа

Нужны Docker и Docker Compose. В корне репозитория создайте локальный `.env` на основе примера:

**PowerShell**

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
docker compose up --build
```

**macOS / Linux**

```bash
test -f .env || cp .env.example .env
docker compose up --build
```

Если `.env` уже существует, сохраните его: команды выше не перезаписывают локальную конфигурацию. Для демонстрации ключ LLM не требуется: в примере включён детерминированный `LLM_PROVIDER=fake`. Не добавляйте реальные ключи в Git. При первом запуске API применяет миграции и загружает демонстрационные данные.

### Подключение LLM-провайдера

Используется ProxyAPI с OpenAI-совместимым API. Чтобы подключить модели, задайте в корневом `.env` параметры:

```dotenv
LLM_PROVIDER=openai_compatible
LLM_BASE_URL=https://api.proxyapi.ru/v1
LLM_API_KEY=ваш-ключ-ProxyAPI
LLM_MODEL=xiaomi/mimo-v2.6-flash
EMBEDDINGS_PROVIDER=openai_compatible
EMBEDDINGS_MODEL=qwen/qwen3-embedding-8b
```

Получите API-ключ в ProxyAPI и укажите его вместо примера; не добавляйте настоящий ключ в Git. Если `.env` ещё не создан, скопируйте `.env.example`, внесите настройки выше и запустите или перезапустите сервисы командой `docker compose up --build`. Для запуска без внешнего провайдера оставьте `LLM_PROVIDER=fake`: ключ и подключение не требуются.

| Сервис | Адрес |
|---|---|
| Веб-интерфейс | http://localhost:5173 |
| API | http://localhost:8000/api |
| Интерактивная документация API | http://localhost:8000/docs |
| MCP-имитация корпоративных систем | http://localhost:8001 |

Compose запускает PostgreSQL, Redis, `mock-corp` (имитация Jira/Confluence/Bitbucket/Mattermost и системы заявок), API и веб-интерфейс. Чтобы остановить сервисы, выполните `docker compose down`. Данные PostgreSQL сохраняются в Docker volume; повторный запуск не сбрасывает их.

### Демонстрационные пользователи

Регистрации и пароля нет. Пользователей можно посмотреть через `GET /api/auth/users`, а войти — через `POST /api/auth/login` с телом `{"user_id":"anya"}`.

| ID | Роль | Для проверки |
|---|---|---|
| `anya` | Стажёр | Основной сценарий, задачи и чек-лист |
| `dima` | Стажёр | Пустые состояния, первая неделя и отсутствие сегодня |
| `boris` | Наставник | Прогресс стажёров и создание задач; доступ к чатам запрещён |
| `maria` | Лид | Проверка ограничений роли |

Все данные синтетические. Документы для демонстрации находятся в [`seed/wiki/`](seed/wiki/), тестовые вопросы — в [`tests/eval/questions.yaml`](tests/eval/questions.yaml), а контракт ручек — в [`API.md`](API.md).

## Порядок ручной проверки

Откройте веб-интерфейс и войдите как `anya`. Для проверки API можно использовать `/docs`; для SSE-ответов удобнее интерфейс.

1. **Запуск и вход.** Убедитесь, что главная страница и список тестовых пользователей открываются.
2. **Ответ с источниками.** Спросите: «Кто отвечает за сервис платежей?». Проверьте карточку человека и ссылки на источники; сохраните контакт в «Знакомствах».
3. **Наводящий режим.** В чате задачи «Платёжный модуль» спросите «Сделай за меня задачу». Проверьте, что ассистент сначала задаёт наводящие вопросы, а затем предлагает прямой ответ и контакт.
4. **Доступ к документам.** Спросите про условия оценки стажёров. Проверьте, что закрытый документ лида не раскрывается.
5. **Заявка на доступ.** Попросите доступ к Jira-проекту PAY. Проверьте черновик, возможность изменить его и необходимость явного подтверждения. Затем запросите доступ к глобальному пространству: заявка не должна создаваться.
6. **Расхождение документов.** Спросите, как получить доступ к тестовому стенду. Проверьте, что показаны варианты инструкций и можно подготовить сообщение владельцу и наставнику.
7. **Отгул.** Попросите создать заявку на отгул. Ассистент должен уточнить недостающие данные и показать черновик до подтверждения.
8. **Журнал.** Создайте запись из чата, удалите чат, затем откройте журнал и проверьте, что запись сохранилась. Проверьте черновик и экспорт PDF.
9. **Приватность и роли.** Проверьте экран приватности. Войдите как `boris`: прогресс стажёра доступен, а запрос чатов должен завершаться отказом `403`.

Подробные примеры запросов и форматов ответов приведены в [`API.md`](API.md).

## Запуск только фронтенда

Чтобы посмотреть UI без запуска API и Docker, используйте локальный мок-режим. Нужен Node.js `>=22.12.0` и npm:

```bash
cd intern-path
npm ci
npm run dev
```

Откройте адрес Vite, обычно http://localhost:5173. Мок-режим включён по умолчанию; состояние хранится в `localStorage` браузера. Для полного прототипа запустите Compose, переключите источник API на «Локальный сервер» на экране входа и используйте серверные демонстрационные аккаунты.

## Тесты, сборка и покрытие

### Backend

Требуется Python 3.12. Команды выполняются из `apps/api`:

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python -m pytest -q --cov=app --cov-report=term --cov-report=xml:coverage.xml --cov-fail-under=80
python -m ruff check app tests
```

В Windows при установленном Python Launcher можно использовать `py -3.12 -m pip ...` и `py -3.12 -m pytest ...`. Backend-тесты используют SQLite в памяти и MCP-имитацию в процессе; CI дополнительно запускает тесты на PostgreSQL. Отчёт XML сохраняется как `apps/api/coverage.xml` и публикуется артефактом CI `coverage-backend`.

### Frontend

Команды выполняются из `intern-path`:

```bash
npm ci
npm run typecheck
npm run test:run
npm run test:coverage
npm run build
```

Vitest измеряет покрытие исходников в `src/`; HTML-отчёт и `lcov.info` находятся в [`intern-path/coverage/`](intern-path/coverage/). Последняя проверка для этого снимка репозитория:

| Компонент | Тесты | Покрытие строк | Дополнительно |
|---|---:|---:|---|
| Frontend | 85 прошли | 89,97% | Statements 89,10%; branches 82,18%; functions 83,60% |
| Backend | 130 прошли | — | Общее покрытие pytest-cov: 94,67% |

Эти числа — результат последнего локального прогона, а не гарантия для последующих изменений. Запускайте команды покрытия после правок; в CI для backend действует порог не ниже 80%.

## Дополнительные команды

```bash
docker compose down                 # остановить сервисы
make test                           # backend-тесты
make coverage                       # backend-тесты с покрытием и coverage.xml
make lint                           # проверка backend через Ruff
make check-llm                      # проверить подключение выбранного LLM-провайдера
docker compose exec api python -m app.cli eval  # eval-набор ассистента (40+ вопросов)
```

Переменные окружения и подключение OpenAI-совместимого провайдера описаны в [`.env.example`](.env.example). Для внешнего провайдера задайте его параметры локально в `.env`; не публикуйте секреты.
